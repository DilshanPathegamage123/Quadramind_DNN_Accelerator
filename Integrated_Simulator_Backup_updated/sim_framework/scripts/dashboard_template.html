Why static placement wins

Bank conflicts are a function of the address pattern

Cycle-exact stall counts over a 200-cycle window with 4 read ports. Because conflicts depend on where tiles sit, a compiler that chooses addresses can eliminate them — a runtime page table cannot.

Read this chart: consecutive access is conflict-free from 4 banks up. Stride-4 is fully serialised at 4 banks — every port maps to the same bank — yet costs nothing at 16. Same hardware, same port count: only the address pattern changed.

Management-logic area, static vs dynamic

Out-of-context synthesis on the ZCU104 target. The shared scratchpad is excluded from both sides, so this is the cost of the management scheme itself. Each scheme is swept over its own capacity knob: metadata entries for static, page-table entries for dynamic.

STAMP (static) PAGED (dynamic)

Banking is close to free — and much faster

A flat scratchpad needs a full-depth multiplexer per read port. Banking splits those into shallow per-bank multiplexers, so it costs less area and closes timing far higher, while also cutting conflicts.

Three independent implementations, one answer

The Python compiler's own bookkeeping, a separately written cycle-accurate model of the controller FSM, and the SystemVerilog hardware running in Vivado xsim. A single disagreement would mean the compiler describes hardware that does not exist.
